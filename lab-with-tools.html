三实操记录一：对简化靶场跑目录爆破

先说一个必须清掉的坑：ffuf 是 Go 程序，会自动读取系统代理环境变量。你本机设了代理，如果不处理，ffuf 访问本地靶场的请求会被代理拦掉（返回 502），你会以为靶场挂了。

# 正确姿势：执行前清掉代理变量
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY='*' \
./ffuf.exe -u http://127.0.0.1:3000/FUZZ -w common.txt -mc 200,301,302,403 -t 20 -rate 150 -s
guestbook
login
orders
robots.txt
search
shop
user

扫出 7 个路径。但注意——靶场里那个备份文件没被扫出来。这是真实工作中最常见的状况：通用字典不可能覆盖所有东西。关键在于接下来的动作。

工具给线索，人做判断

扫出来的结果里有个 robots.txt。工具到此为止，接下来是人去看：

GET http://127.0.0.1:3000/robots.txt

User-agent: *
Disallow: /backup/
Disallow: /admin/
robots.txt 是"此地无银三百两"。它本来是写给搜索引擎看的，但内容对所有人公开——等于站方主动列出"这里有我不想让人看见的东西"。Disallow 的路径永远是第一优先级的探测目标。

拿到 /backup/ 这条线索，做第二次爆破，这次带后缀扩展：

env -u HTTP_PROXY -u HTTPS_PROXY NO_PROXY='*' \
./ffuf.exe -u http://127.0.0.1:3000/backup/FUZZ -w common.txt \
  -e .bak,.zip,.old -mc 200,301,302,403 -t 40 -rate 900 -s

config.bak          ← 命中

-e 的作用是自动给每个字典词追加后缀，一次请求覆盖 config、config.bak、config.zip、config.old 四种可能。备份文件泄露的拿分效率很高，因为它的价值不取决于技术难度，而取决于文件里有什么。

四实操记录二：对 Juice Shop 跑目录爆破（含一个真实的坑）

Juice Shop 是单页应用（SPA）。直接扫会掉进一个坑，先探测一下：

for p in /this-path-does-not-exist-xyz123 /totally-fake-page /nonexistent; do
  curl -sS --noproxy '*' -o /dev/null -w "$p → HTTP %{http_code}  %{size_download} bytes\n" "http://127.0.0.1:3001$p"
done

/this-path-does-not-exist-xyz123 → HTTP 200  9426 bytes
/totally-fake-page               → HTTP 200  9426 bytes
/nonexistent                     → HTTP 200  9426 bytes

# 对比首页
curl -sS --noproxy '*' -o /dev/null -w "首页 → HTTP %{http_code}  %{size_download} bytes\n" http://127.0.0.1:3001/

首页 → HTTP 200  9426 bytes
坑在这里：SPA 路由把所有不存在的路径都交给前端处理，统一返回 200 + 首页（9426 字节）。
如果你直接跑 ffuf -mc 200，4751 个字典词会全部"命中"——扫描结果完全没用，你还以为自己扫到了全站。
解法：用 -fs 9426 把这个"兜底页"的大小过滤掉。这是真实项目里扫 SPA 站点的必备动作，很多新手就是在这里被卡住，然后得出"这个站没东西"的错误结论。
# 正确姿势：按响应大小过滤掉 SPA 兜底页
env -u HTTP_PROXY -u HTTPS_PROXY NO_PROXY='*' \
./ffuf.exe -u http://127.0.0.1:3001/FUZZ -w common.txt \
  -mc all -fs 9426 -t 40 -rate 800 -s

过滤之后，结果就干净了。本次实际扫出：

状态码发现的路径
200/ftp、/promotion、/robots.txt、/video、/.well-known/security.txt
301/assets、/media
500/api、/api/experiments、/rest、/profile、/redirect —— 500 是好信号，说明接口存在但你没给对参数
关于 500：新人常把 500 当成"站点坏了"直接略过。恰恰相反——500 意味着"这个接口真实存在，只是我调的方式不对"。它是接口挖掘里最有价值的信号之一。同理，403 也不是"没有"，而是"有，但被规则挡住了"，值得尝试绕过。

五实操记录三：深挖 /ftp（403 的判读与字典的局限）

上一轮扫出的 /ftp 是 Juice Shop 的一个经典入口。先看它对不存在文件的响应：

curl -sS --noproxy '*' -o /dev/null -w "%{http_code} %{size_download}\n" http://127.0.0.1:3001/ftp/nonexistent-xyz

403 2537       ← 任何不在白名单里的文件都返回 403

所以做文件爆破时，不能过滤 403，只能保留 200：

env -u HTTP_PROXY -u HTTPS_PROXY NO_PROXY='*' \
./ffuf.exe -u http://127.0.0.1:3001/ftp/FUZZ -w common.txt \
  -e .md,.bak,.yml,.json -mc 200 -t 40 -rate 900 -s

Legal.md
legal.md

字典加后缀一共 2 万多次请求，只发现了 legal.md。但这不代表没有别的——手工验证几个常见文件名：

for f in legal.md acquisitions.md announcement_encrypted.md package.json.bak coupons_2013.md.bak; do
  printf "%-32s %s\n" "$f" "$(curl -sS --noproxy '*' -o /dev/null -w 'HTTP %{http_code}  %{size_download} bytes' "http://127.0.0.1:3001/ftp/$f")"
done

legal.md                         HTTP 200  3100 bytes
acquisitions.md                  HTTP 200  928 bytes          ← 字典没覆盖到
announcement_encrypted.md        HTTP 200  370431 bytes       ← 字典没覆盖到，370KB
package.json.bak                 HTTP 403  2536 bytes         ← 被 deny 规则拦住
coupons_2013.md.bak              HTTP 403  2536 bytes         ← 被 deny 规则拦住
这一轮演示了三件事：
① 字典决定你的视野。common.txt 里没有 acquisitions，所以 ffuf 扫不到它——不是站点没这个东西，而是你的字典不够。真实项目里要按目标特征定制字典。
② 403 值得继续追。package.json.bak 和 coupons_2013.md.bak 都返回 403，说明它们确实躺在那个目录里，只是被规则挡住了。Juice Shop 恰好把"绕过这个 deny 规则"做成了一个挑战——值得你自己去试（提示：URL 编码相关）。
③ 大文件是信号。370 KB 的 announcement_encrypted.md 明显不是一份普通公告，里面藏着东西。

六从这次实操里提炼的四条

要点为什么
先探测基线，再扫描不先搞清楚"正常的和不存在的长什么样"，就没法设置过滤条件。SPA 兜底页那个坑就是这么掉进去的
状态码要分类读200 = 存在；301/302 = 跳转，跟过去看；403 = 有但被拦；500 = 接口在，参数不对。只有 404 才是真的没有
工具只给线索本次两个关键收获——/backup/config.bak、/ftp/acquisitions.md——都是人看过工具输出之后手工验证出来的，不是工具直接给的
字典是能力边界换更贴合的字典，或按目标特征自己写词表，往往比调工具参数有用得多

七怎么自己重跑

启动靶场

双击项目根目录的 启动靶场.bat（我新加的），会同时起两个靶场并提示地址。Juice Shop 启动约需 20 秒（要初始化数据库），日志在 tools/js.log。

ffuf 常用命令

# 1. 目录爆破（通用）
env -u HTTP_PROXY -u HTTPS_PROXY NO_PROXY='*' ./ffuf.exe \
  -u http://目标/FUZZ -w common.txt -mc 200,301,302,403 -t 20 -rate 150 -s

# 2. 带后缀扩展（找备份文件）
... -u http://目标/FUZZ -w common.txt -e .bak,.zip,.old,.sql,.tar.gz

# 3. SPA 站点：按响应大小过滤兜底页
... -mc all -fs <兜底页大小>

# 4. 参数爆破（找隐藏参数）
... -u "http://目标/api?FUZZ=1" -w 参数名字典

# 5. 只看结果、导出 CSV 留档
... -s -of csv -o result.csv
参数作用
-mcmatch codes，只显示这些状态码。用 all 表示全都看
-fs/-fc过滤指定响应大小 / 状态码。扫 SPA 必备
-e自动追加后缀，如 .bak,.zip
-t / -rate并发数与每秒请求上限。打真实项目必须限速，本地靶场随意
-s静默模式，只输出命中结果，不被进度刷屏
-of csv -o x.csv导出结果留档，方便回看和写报告

八下一步：把 Juice Shop 接进 Burp

ffuf 这类工具只能帮你"找门"，真正的漏洞还得靠手工。Juice Shop 有 100+ 个挑战，是练手工最好的靶场之一。装上 Burp 后：

  1. 打开 Burp 内置浏览器（Proxy → Intercept → Open browser），不用配证书
  2. 访问 http://localhost:3001，把注册、登录、搜索、加购物车、下单、提交评论、上传头像全走一遍
  3. Target → Scope 填 localhost，把无关流量滤掉
  4. 在 HTTP history 里挑带参数的请求，Ctrl+R 丢进 Repeater，然后按"改值 / 改身份 / 改顺序 / 改类型"四个方向挨个试

Juice Shop 自带计分板和提示系统，右上角 Score Board 能看到自己解开了哪些挑战。从"搜索框做 SQL 注入"和"用别人的购物车 ID"这两个开始最合适。

提醒：Juice Shop 官方还提供了一个在线 Demo 站。那个是公开实例，不要拿它练手——官方只允许浏览，不允许扫描或攻击。用你本地这个，怎么打都没事。
