【必读前提】
  下面这些靶场都是"故意做出来的漏洞环境"，专门给人打的。打它们完全合法。
  但在真实网站上，同样的操作没有授权就是违法（《刑法》285 / 286 条）。
  靶场的唯一价值，是让你在合法环境里把技术练成肌肉记忆，然后去 SRC 授权范围内用。
  超过这个边界，一切技术都没有意义。

【本机环境提示】
  当前电脑有 Node.js 22，但**没有 Docker、没有 PHP、没有 Java**。
  第一章的多数靶场依赖 Docker，需要先安装 Docker Desktop（Windows）才能跑。
  第二章的在线平台无需任何安装，现在就能开始。

第五章  合法的真实战场（把上面练熟之后再来）
================================================================================

  可以打的：
    · 补天「专属 SRC」/ 漏洞盒子的企业项目 —— 企业主动入驻并明确授权，
      是真实系统上唯一正规的入口
    · 火线安全平台上企业发布的公开项目

    · 「公益 SRC」类投稿 —— 那是平台代为转交，目标站点本身并没有直接
      授权你去测试，法律边界模糊。练技术请用靶场，别拿这个练。

  铁律：每个项目的 scope（测试范围）是硬约束。
        范围外的域名、IP、内网，一个包都不能发。

第六章  怎么在这些靶场里找漏洞  ← 核心方法论
================================================================================

--------------------------------------------------------------------------
一、通用流程（所有靶场通用，六步）
--------------------------------------------------------------------------
  第 1 步  先"读"再"打"
    把靶场的每个菜单点一遍，列出它有哪些功能：
      登录 / 注册 / 搜索 / 查询 / 上传 / 留言 / 下单 / 修改资料 / 找回密码……
    能看源码的（Pikachu、upload-labs、DVWA）一定要先读源码 ——
    这是最快的路，你会直接看到防护写在哪一行、漏在哪一行。

  第 2 步  建立"参数清单"
    每发现一个能提交的参数就记下来：它叫什么、在哪、什么类型、可能去哪。
    打靶场的核心动作，就是拿着这张清单一个一个试。

  第 3 步  四个方向逐个试（最关键的一步）
    ① 改值   —— 改成 0 / -1 / 超大数 / 超长串 / 特殊字符 / 空值 / 数组
    ② 改身份 —— 把 id、uid、orderId、role 换成别人的或管理员的
    ③ 改顺序 —— 跳步（下单不付款直接确认）、重复提交、并发提交（竞态）
    ④ 改类型 —— 数字改成字符串、false 改成 true、删掉字段、多传一个字段

  第 4 步  盯"预期之外"的反应
    · 报错信息 —— 数据库类型、物理路径、框架版本，全是情报
    · 返回包里的多余字段 —— 页面没显示，但接口返回了（越权和信息泄露的高频入口）
    · 响应时间差异 —— 时间盲注的唯一信号
    · 状态码与文案不一致 —— 提示"失败"但返回结构像成功

  第 5 步  验证到"最小可复现"就停手
    拿到能证明漏洞存在的最小证据即可。不要顺手把数据拉空、不要删别人数据。
    这一步是在练习惯：真实 SRC 上多拉一条数据都可能被判定违规。

  第 6 步  写 writeup
    每个靶场都写：漏洞位置、复现步骤、原理、修复建议。
    写不出来 = 没真懂。这是检验学习效果最准的一把尺子。

--------------------------------------------------------------------------
二、各类漏洞的"入门切入点"（讲思路，不是给你 payload 集）
--------------------------------------------------------------------------
  SQL 注入
    先判断这个参数有没有进数据库。输入单引号看是否报错；
    用 1=1 与 1=2 对比返回结果是否不同；再判断能不能拼接出额外数据。
    关键词是"返回差异"，不是"背语句"。

  XSS
    唯一难点是**判断输入被放在什么上下文**：
    HTML 正文里？标签属性里？JS 代码里？URL 里？
    不同上下文的绕过方式完全不同。先定位上下文，再想怎么闭合。

  文件上传
    先看它拦的是什么 —— 后缀？Content-Type？文件头？内容关键词？
    找到"它拦的那一条"，就知道该绕哪一条。

  越权
    靶场通常给你两个账号。用 A 的会话去访问 B 的资源（水平越权）；
    用普通账号去访问管理员接口（垂直越权）。
    重点关注参数名：id、uid、orderId、role、deptId、menuCode。

  业务逻辑漏洞
    先把正常流程画出来（浏览 → 下单 → 支付 → 完成），
    然后专挑三类地方：流程能不能跳步、金额能不能改、操作能不能重复。

  信息泄露
    翻 robots.txt、翻 JS 文件里的接口路径、翻报错页面、
    翻源码注释、翻 .git / .bak / .swp / 备份压缩包。

  真实 CVE（Vulhub 场景）
    先在靶场里把漏洞跑起来，看清版本号、请求特征、响应特征，
    再去真实授权目标上比对指纹。

三、第一次练手的具体安排（照着做就行）
--------------------------------------------------------------------------
  第 1 天      装 Docker → 起 DVWA → 难度调 Low → 8 个模块全打一遍
              （照提示做也行，这个阶段的目标是"走通流程"）
  第 2~4 天    同一批模块切到 Medium 和 High，自己想办法绕过
              ★ 这一步才是真正开始学东西的地方
  第 5~7 天    起 Pikachu，把中文分类过一遍，补齐 DVWA 没覆盖的
              （SSRF、XXE、反序列化、越权）
  第 2~3 周    注册 PortSwigger Academy，按路径刷
              SQLi → XSS → CSRF → SSRF → XXE，每类至少做到 Practitioner
  第 4 周起    起 OWASP Juice Shop，不看攻略刷挑战分（最接近真实业务）
  之后          Vulhub 挑感兴趣的 CVE 复现 + CTFHub 技能树系统性补漏
              + 去 TryHackMe / HTB 打完整靶机

四、让练习效果翻倍的 4 个习惯
--------------------------------------------------------------------------
  1. 写详细笔记（Markdown 记命令、思路、踩的坑），笔记是二次思考
  2. 每攻破一个，去看别人的 writeup，找"第二种解法"，照着他的方法再做一遍
  3. 卡住超过半天再看提示，不要一卡就搜答案 —— 卡住的过程就是学习本身
  4. 一个漏洞打通后，回去读它的"防御写法"
     （DVWA 的 Impossible 档就是专门干这个的）
     懂防御的人才挖得到更深的洞


================================================================================
第七章  新手最容易踩的五个坑
================================================================================

  1. 只刷关卡、不学原理        → 换个场景立刻失效
  2. 过度依赖 sqlmap / 扫描器  → 真实平台上"扫描器发现的问题"基本不收，
                                  而且会触发风控封号
  3. 只盯着能不能 getshell    → 大量真正值钱的洞是信息泄露和越权，
                                  根本不需要打进服务器
  4. 靶场打爽了就去打真实网站  → 唯一的"一票否决"级错误
  5. 装一堆工具                → Burp Suite 社区版 + 浏览器 F12 + 一点 Python
                                  足够支撑很长的学习阶段
