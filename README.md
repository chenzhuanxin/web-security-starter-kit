## 一、这是什么

这是一套**完整的 Web 安全入门资料集**，回答一个具体的问题：

> 网上说「找网站漏洞提交能赚钱」，这条路到底是怎样的？我该怎么真正学会它？

它不是零散的知识点罗列，而是一条**从认知到动手的完整链路**：先搞清楚这个行业的真实收入结构和法律边界，再拿到所有正规平台的入口，然后用一套实测过的靶场清单练技术，最后看着真实的请求与响应走通一遍全流程。

全部内容基于**实机实测**：38 个靶场网址逐一验证过可访问性，失效的已标注；工具链在本机真实跑通并留下了原始输出；配套靶场的 7 个关卡是真实打通后记录的，不是照着手册想象的演示。

## 四、配套靶场 vulnlab

仓库里带了一个**可以立刻运行的 7 关入门靶场**，是 [lab-walkthrough.html](lab-walkthrough.html) 的实操对象。

### 关卡设计

每一关都对应一个真实世界里高频出现的缺陷类型：

| # | 关卡 | 考什么 | 真实世界里的对应 |
|---|---|---|---|
| 1 | 弱口令登录 | 管理员用了弱密码 | 运维图省事留下的默认口令 |
| 2 | SQL 注入 | 输入被字符串拼接进 SQL 语句 | 最经典、危害最大的注入类漏洞 |
| 3 | 越权访问（IDOR） | 把订单号换成别人的照样能看 | **新手最容易出成果的方向** |
| 4 | 金额篡改 | 价格由浏览器提交，服务端直接采信 | 业务逻辑漏洞，任何扫描器都发现不了 |
| 5 | 反射型 XSS | 输入被原样当代码回显 | 最常见的低危漏洞 |
| 6 | 存储型 XSS | 恶意内容入库并对所有访客生效 | 危害远超反射型 |
| 7 | 敏感文件泄露 | 备份文件没做访问控制 | 常在信息收集阶段就被发现 |

首页有**实时通关进度**（0 / 7），每关都带提示，卡住了看一眼就够。

### 运行方式

```bash
cd vulnlab
node server.js
```

然后浏览器打开 **http://localhost:3000**。

**环境要求**：Node.js 18 或更高版本。**没有其他任何依赖**——不需要 Docker、不需要 MySQL、不需要安装任何 npm 包，单个文件就是全部。

### 其他说明

| 项 | 说明 |
|---|---|
| 监听地址 | 仅 `127.0.0.1:3000`，**外网访问不到**，不会暴露给局域网或互联网 |
| 重置进度 | 访问 `http://localhost:3000/reset`，会同时清空通关记录和留言板数据 |
| 状态存储 | 内存中，**重启进程即全部归零** |
| 是否含答案 | 关卡名称和提示直接写在页面里；完整解法与 payload 见 `lab-walkthrough.html` |

## 五、推荐阅读顺序

如果你完全从零开始，按这个顺序走，不要跳：

```
第 1 步  读 platforms.html
         先弄明白这个行业真实的收入和门槛，确认自己要不要投入

第 2 步  读 labs-list.txt 的第一、二章
         挑一个靶场。零安装起步就选 PortSwigger Web Security Academy
         或 CTFHub；想立刻动手就跑本仓库自带的 vulnlab

第 3 步  打 vulnlab 的 7 关，卡住看首页提示
         打完对照 lab-walkthrough.html 复盘每一步

第 4 步  读 labs-list.txt 第六章（核心方法论）
         把「改值 / 改身份 / 改顺序 / 改类型」四个方向变成条件反射

第 5 步  读 toolkit.html，装 Burp Suite
         用 Repeater 把 7 关重做一遍，这次不许用 curl

第 6 步  读 lab-with-tools.html
         看真实工具怎么用、怎么判断它的输出

第 7 步  在平台注册账号，先只读规则和别人已公开的报告
         确认理解了 scope，再考虑动手
```

**不要跳过第 1 步。** 先搞清楚边界和预期，比先学会技术重要得多。

## 七、技术说明

### 站点实现

全部文档是**纯静态 HTML / TXT**，没有构建步骤、没有依赖、没有框架。样式全部内联，不引用任何外部资源——这意味着：

- 克隆下来直接双击就能看，不需要起服务器
- 可以离线使用
- 不依赖任何 CDN，不会因为外部资源失效而样式崩坏

### GitHub Pages 部署

站点通过 GitHub Pages 从 `main` 分支根目录直接发布。

由于本机网络环境下 `github.com` 的 git 传输被代理阻断，仓库的创建与文件上传是通过 **GitHub REST API**（Contents API + Pages API）完成的，而不是 `git push`。对应的部署脚本逻辑要点：

1. 用 `gh auth token` 取凭据
2. `GET /user` 确认身份
3. 仓库不存在则 `POST /user/repos` 创建，存在则跳过（幂等）
4. 逐个文件 `GET /contents/<path>` 查 sha → 有 sha 走更新、无 sha 走新增
5. `POST /repos/{owner}/{repo}/pages` 开启 Pages，轮询直到 `status == built`

### 更新站点

改完 `outputs/` 下的文件后重新执行部署脚本即可，会按 sha 判断哪些文件需要更新，已存在的不会重复创建。Pages 每次提交会自动重新构建，约 30–60 秒生效。

## 八、编写原则

这份套件里所有事实性内容都遵循三条：

**1. 链接必须实测。** 38 个靶场网址、18 个平台官网、十几个工具地址，全部用脚本逐一探测过 HTTP 状态码。已失效的（如 `hackinglab.cn`、`vulfocus.cn` 在线版、`hackthissite.org`）在文档里单独标注，而不是混在列表里让你自己踩空。GitHub 仓库则用 API 核实存在性与活跃度，顺手纠正了一个网上流传的错址（云原生靶场 Metarget 的正确地址是 `Metarget/metarget`，不是 `brant-ruan/metarget`）。

**2. 操作必须真跑。** 7 关靶场的每一次请求、Juice Shop 的每一次 ffuf 扫描，都是真实发出并留档了原始响应。包括失败和踩坑的部分——比如哪个文件第一轮没被扫出来、为什么会被扫成"全部命中"、代理变量如何让工具误报 502。**失败的分支往往比成功的分支更值得记录。**

**3. 环境必须匹配。** 工具清单是按实际机器环境裁剪的，不是通用推荐。本机没有 Docker / Java / PHP，所以本地靶场选中了唯一能跑的 Node 原生方案；也因为如此，才会明确指出「Go 系工具都是免安装单文件 exe、Burp 自带 JRE」，避免因为缺运行时就把一大批工具判死。

## 九、常见问题

**Q：跑这个靶场需要装 Docker 吗？**

不需要。`vulnlab/server.js` 是零依赖的，只要有 Node.js 18+ 就能跑。仓库里也没有打包任何需要 Docker 的靶场，因为那些动辄几百 MB，不适合放在仓库里——完整清单在 [labs-list.txt](labs-list.txt) 里，按需自取。

**Q：我能用这里学到的技术去测试某个真实网站吗？**

**不能。** 只有三种情况可以动手：目标在平台明确列出的授权范围内、是你自己的资产、或拿到了站点方的书面授权。三者之外，哪怕只是一个不起眼的小官网，第一个数据包就是**非法侵入计算机信息系统**。用漏洞向企业索取财物属于**敲诈勒索**，不是漏洞赏金。技术和犯罪的边界不在技术本身，只在「有没有授权」这一条线上。

**Q：为什么仓库里的文件名是英文，站点上却是中文？**

中文文件名在 URL 中需要百分号编码，容易出错且可读性差，所以仓库内统一用 ASCII slug（如 `labs-list.txt`）。中文标题在首页上原样保留，点击进入的阅读体验不受影响。

**Q：网站打不开 / 样式错乱怎么办？**

先确认访问的是完整地址（末尾带 `/`）。Pages 每次更新需要 30–60 秒构建时间，刚更新完可能短暂不可用。也可以直接把仓库克隆到本地，双击 `index.html` 即可离线浏览。
