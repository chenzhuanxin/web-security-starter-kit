真实项目挖洞：工具与操作手册

按你本机实测环境定制  ·  所有工具地址已逐一验证  ·  适用范围：平台或站点方明确授权的目标

先说清楚这份手册的适用边界。下面所有工具和手法，只有在你具备下列身份之一时才可以使用：
① 目标是官方 SRC / 众测平台上的项目，且在其公布的 scope 内；② 目标是你自己拥有的资产；③ 你有站点方的书面授权。

一先确认授权：授权范围里有什么

新人拿到一个项目，第一件事不是装工具，是把 scope 抄成一张表。这不是形式主义——测试中被平台扣分甚至永久封号，绝大多数是因为"越界"而不是"技术差"。

要素要确认什么越界后果
资产范围具体是哪些域名、IP、APP、小程序？通配符 *.a.com 是否包含子域的子域？收购来的老域名算不算？测试范围外资产 = 犯罪
端口 / 协议是否允许扫全端口？是否允许测非 Web 服务？被判定扫描滥用，扣分
测试类型是否允许自动化扫描器？是否允许口令爆破？是否允许上传 webshell？违反规则，报告被判无效
时间窗口项目起止时间，是否有"仅夜间测试"的要求窗口外提交不予受理
禁止事项是否禁止社工、禁止 DoS、禁止触碰真实用户数据、禁止横向渗透到内网最严重，可能直接法律追责

把 scope 抄成这张表，测的时候放在旁边

项目填写
平台 / 项目名—
授权域名 / IP—
明确排除的资产—
是否允许自动化扫描—
是否允许口令爆破—
并发 / 速率限制—
测试时间窗口—
报告提交入口—
一条实战经验：不确定某个资产在不在范围内时，先提交工单问平台，而不是"试一下再说"。问了不丢分，试错了丢号。

① 抓包改包 —— 这是主战场，占你 70% 的时间

Burp Suite Community本机可直接装必装

Web 安全测试的事实标准。核心就三个功能：Proxy（截获流量）、Repeater（改一个参数重放，最重要）、HTTP history（回看刚才发了什么）。社区版免费，Repeater 完整可用，只限制 Intruder 的速度和项目保存——对新手完全够。

portswigger.net/burp/communitydownload

OWASP ZAP备选

同样免费开源的抓包代理，功能对应 Burp，界面稍笨重。Burp 装不上时的替代品。
zaproxy.org/download/

浏览器插件可选

FoxyProxy——一键在"直连 / 走 Burp"之间切换代理，省得每次改系统设置（本机访问其官网不通，可从浏览器扩展商店搜装，装不上也无所谓）。
Wappalyzer——识别网站用了什么框架、中间件、CDN，做指纹用。
wappalyzer.com

② 信息收集 —— 决定你能看到多少资产

subfinder免安装 exe高频使用

子域名枚举。目标主站防护严，但它的某个测试子域、老旧子域往往无人看管，是出洞最多的地方。14.5k 星，项目仍在活跃维护。
github.com/projectdiscovery/subfinder

httpx免安装 exe高频使用

把枚举出来的几万个子域快速探活，并抓取状态码、标题、技术栈。作用是把海量域名收敛成几十个真正值得看的站点。
github.com/projectdiscovery/httpx

空间测绘平台浏览器直接用

FOFA、Hunter、Quake、Shodan——按"网站图标特征 / 证书 / 页面关键词"反查同一单位的其他资产。能发现主域名之外、你根本想不到的暴露面。
fofa.info · quake.360.net · www.shodan.io
注hunter.how 对脚本返回 403（浏览器正常）；zoomeye.org 当前源站 521 打不开，跳过即可。

OneForAll需 Python 环境

国产子域枚举整合工具，把几十个数据源和爆破方式打包在一起，比 subfinder 更"暴力"。10k 星。但对目标请求量大，用之前先确认项目允许。
github.com/shmilylty/OneForAll

③ 目录与接口发现 —— 找"藏起来的入口"

dirsearchPython，本机可跑高频使用

目录/文件爆破，自带后缀字典（.bak、.zip、.old 等）。14.8k 星，今天还在更新。找备份文件、后台入口、未授权接口全靠它。
github.com/maurosoria/dirsearch

ffuf免安装 exe

更快的爆破器，可对目录、参数、子域、POST 字段做 fuzz。自带速率限制参数，适合在"允许扫描但限速"的项目里精细控制。
github.com/ffuf/ffuf

katana / gau免安装 exe

katana：爬虫，能把一个站点爬出上万条 URL，还能解析 JS 里的接口。gau：从 Wayback Machine 等历史归档里捞出老 URL——很多早已下线的接口其实还活着，而且没有防护。
github.com/projectdiscovery/katana · github.com/lc/gau

LinkFinder / JSFinder需 Python 环境

专扒 JS 文件里藏着的前端接口路径和密钥。现代站点权限校验常放在前端，看一眼 JS 就能找到一堆后端接口。
github.com/GerbenJavado/LinkFinder · github.com/Threezh1/JSFinder

④ 漏洞验证 —— 注意：这一类工具在平台上争议最大

务必先读平台规则。下面这些自动化扫描器，多数 SRC 和众测平台明确禁止使用，或者明确声明"扫描器发现的问题不计分"。而且大量扫描极易触发目标的风控、影响业务、被判定为攻击行为。
正确用法：把它们当"线索发现器"，发现有价值的结果后，用手工在 Burp 里复现一遍，用复现结果去提交。绝不要直接把扫描器输出贴进报告。

nuclei免安装 exe平台接受度低

基于模板的漏洞扫描，用于快速排查目标是否命中已知 CVE。只在项目明确允许扫描时用，且必须限速。
github.com/projectdiscovery/nuclei

sqlmap高危，慎用

SQL 注入自动化。功能强大但流量特征极明显，在真实目标上使用前必须先确认平台允许，且严格限制等级和注入技术。多数情况下，手工加一个单引号探测 + Burp 重放就足以证明漏洞存在，不必动它。
sqlmap.org

nmap需安装

端口与服务识别。用于摸清目标开放了哪些服务。-T3 或更低，别用激进模式。
nmap.org/download.html

⑤ 记录与报告 —— 决定你能拿到多少钱

Burp 自带 + 截图工具

每个漏洞固定留四样东西：完整 URL、原始请求包、关键响应、复现步骤截图。这四样不齐，报告大概率被驳回。
XSS 类漏洞必须有浏览器截图——证明"脚本真的执行了"，而不是仅仅被回显。

四完整操作流水线：一个项目从 0 到交报告

下面 8 个阶段是一个真实项目的标准动作顺序。注意时间分配：真正的"攻击"只占很小一部分，前面全是在看。

0

读 scope，建资产白名单

把第一章那张表填满。把授权域名写成一个文件，后面所有命令都从这个文件读——这样你能一眼看到自己有没有越界，也能在报告里说明"我测的资产在范围内"。

# scope.txt —— 只有这里面的资产可以碰
example.com
admin.example.com
*.api.example.com
1

子域名枚举：把资产面铺开

$ subfinder -d example.com -all -recursive -o subs.txt

# 合并你从空间测绘平台、证书透明度日志里手动找到的结果
$ cat fofa_results.txt >> subs.txt
$ sort -u subs.txt -o subs.txt && wc -l subs.txt

为什么这步最值钱：主站防护严密、天天被人盯着，但一个 test-2021.example.com 可能三年没人维护。攻击面永远在边上，不在正门。

提醒这一步只查公开的 DNS 记录和第三方数据源，不向目标发包，是合规成本最低的一步。

2

存活探测 + 指纹识别：把几万个收敛成几十个

$ httpx -l subs.txt -status-code -title -tech-detect -o alive.txt

https://admin.example.com  [200] [管理后台] [Vue, Nginx]
https://test.example.com   [200] [phpMyAdmin] [PHP, MySQL]    <-- 这个值得重点看
https://old.example.com    [403] [Forbidden]                  <-- 403 也可能是被拦截的真入口

输出里的每一列都是情报：状态码告诉你活着没有，标题直接暴露这是一个管理后台还是报错页，技术栈决定你该去找哪类漏洞（PHP 找文件上传，Java 找反序列化）。

3

端口与服务扫描（若项目允许）

$ nmap -sV -Pn -T3 --top-ports 1000 -iL ips.txt -oN ports.txt

-T3 是刻意选的保守速度。别用 -T4/-T5 或 -A，那会明显加重目标负载，容易被风控抓到。发现非 Web 端口（数据库、Redis、ES）先别急着连——很多项目禁止触碰。

4

目录与文件爆破：找没关好的门

$ dirsearch -u https://test.example.com \
  -e php,asp,aspx,jsp,html,js,zip,bak,old,txt,sql,git \
  -t 10 --random-agent

# 或 ffuf，能显式限速（推荐在限速项目里用）
$ ffuf -u https://test.example.com/FUZZ -w common.txt \
  -mc 200,301,302,403 -rate 20 -o dir.json

只看 200 会漏掉一半东西。403 常意味着"文件在，但你没权限"——换个路径大小写、加个斜杠、换个请求方法就可能有戏。目录爆破的经典收获：.git/、.env、backup.zip、phpinfo.php、debug.log。

5

URL 与接口采集：把功能点全捞出来

$ katana -u https://test.example.com -d 3 -jc -o crawl.txt
$ gau example.com > urls.txt

# 从采集结果里挑出"带参数"的 URL —— 这些才是可测试点
$ cat crawl.txt urls.txt | grep "?" | sort -u > params.txt
$ wc -l params.txt

-jc 是解析 JS 里的链接，这一步经常能扒出前端调用、但页面上没有的后端接口。带参数的 URL 就是你的"测试清单"，每一个参数都要过一遍后面的"四个方向"。

6

手工测试 —— 真正的时间黑洞，也是唯一出成果的地方

打开 Burp，用它内置的浏览器（连证书都不用装），然后像正常用户一样把目标站点的功能全部走一遍：注册、登录、改资料、下单、上传、搜索、分享、导出、支付……

每走到一个功能点，就在 Repeater 里问那四句话：

方向在 Burp 里具体改什么典型命中
改值数字改 0 / -1 / 超大数；字符串加 ' " <>；留空；超长SQL 注入、逻辑漏洞、XSS
改身份id / uid / userId / orderId / role 换成别人的、改成 0 或 1越权（新手出成果最多的方向）
改顺序跳步调用接口、重复提交、并发提交、把"需验证"的步骤直接跳过业务逻辑、支付绕过
改类型数字→字符串、false→true、删掉某个字段、多传一个字段校验绕过

还有一个必做动作：在浏览器里登录普通账号，然后对比接口响应里"页面没显示但返回了"的字段——手机号、邮箱、内部 ID、角色标识经常就藏在里面。这是信息泄露和越权的最高频入口。

7

验证到"最小可复现"就停手

这是区分专业和业余的地方。证明漏洞存在所需的信息就够了，多取一条都是风险。

  • SQL 注入：能取到库名或表名即止，绝不 dump 用户数据；
  • 越权：能看到别人的一条无关紧要的记录即止，不要批量遍历；
  • 文件上传：上传一个内容为空的验证文件即止，不要传 webshell、不要执行命令；
  • 信息泄露：只看响应头或字段名，不要下载完整数据包；
  • 任何涉及批量的操作，提前向平台报备。

然后清理现场：删除你上传的文件、退出你创建的测试账号。好的测试者走的和来的时候一样干净。

8

写报告提交

按固定结构写：漏洞名称 / 类型 / 危害等级 / 完整 URL（含参数）/ 复现步骤 / 危害说明 / 修复建议 / 附件截图。

三个必须做的事：

  • 提交前先在平台漏洞库搜关键词查重——撞车会被判重复，白白扣分；
  • 截图里必须能看到完整 URL，标注清楚每一步；
  • 修复建议要具体到"用什么方法"（如"使用参数化查询"），不要写"加强安全防护"。

五Burp 手把手：装完之后手往哪放

1

下载安装

打开 portswigger.net/burp/communitydownload，选 Windows 安装包。官方包自带运行环境，你机器上没有 Java 也能装。

2

启动配置

启动后选 Temporary project → Use Burp defaults。社区版不支持保存项目，关掉重开就是新的，对你够用。

3

用内置浏览器（强烈推荐，省掉最容易卡住的一步）

切到 Proxy → Intercept 标签，点 Open browser。Burp 会打开自带配置好的 Chromium——代理和证书都配好了，你什么都不用管。

如果坚持用自己的 Chrome：需要两步——① 用插件或系统设置把代理指向 127.0.0.1:8080；② 浏览器访问 http://burp 下载 CA 证书并导入到"受信任的根证书颁发机构"，否则所有 HTTPS 站点都会报证书错误。这步新手最容易失败，所以更建议直接用内置浏览器。
4

设置 Target Scope —— 这一步是给自己上保险

Target → Scope → Add，把授权域名填进去，勾选 Use suite scope。
作用有两个：一是过滤掉无关流量（你浏览器里的其他标签页、浏览器自己的更新请求）不会污染历史记录；二是让你一眼看清自己在打谁——所有记录下来的请求都在 scope 内。

5

正常浏览，让流量自然产生

Proxy → HTTP history。别急着改包，先把网站当正常产品用一遍。看到感兴趣的请求（带参数的、返回 JSON 的、有 token 的），右键 → Send to Repeater（快捷键 Ctrl+R）。

6

在 Repeater 里做"四个方向"

左边是原始请求，改完点 Send，右边就是响应。改一个参数、看一次结果、判断一次——这就是全部的核心循环。

# 原始请求
GET /api/order?id=1001 HTTP/1.1
Host: target.example.com
Cookie: session=abc123

# 第 1 次改动：换 id（测越权）——  改完点 Send，看响应里是不是别人的数据
GET /api/order?id=1002 HTTP/1.1

# 第 2 次改动：加个引号（测注入）——  看响应有没有报错
GET /api/order?id=1001' HTTP/1.1

# 第 3 次改动：换成不存在的 id（测异常处理）——  看会不会炸出堆栈信息
GET /api/order?id=99999999 HTTP/1.1

判断要点：不要只盯状态码。响应长度变了、返回了页面没显示的字段、报错信息泄露了路径——这三种"预期之外的反应"才是真正的信号。

7

用 HTTP history 回头补漏

测完一轮，回 HTTP history 按状态码或关键词过滤，重新审视那些你刚才没在意的请求。很多洞是第二轮才看出来的，因为第一轮你还不知道自己在找什么。

六测试纪律：比工具重要得多的一段

纪律具体做法
限速并发控制在 5 以内，ffuf -rate 20、dirsearch -t 10。绝不允许因为你的测试导致目标变慢或不可用——这是最常见的封号原因
只验证不深入证明存在就停。不进数据库翻数据、不横向移动、不尝试提权到服务器
不碰真实用户数据看到别人的手机号、身份证号，只看一条、不保存、不截图敏感内容，报告里打码
不越界扫描前对照 scope 表。发现范围外的资产，停下来先问平台
不用社工不钓鱼、不骗客服、不撞库其他平台泄露的密码。这是红线中的红线
不做 DoS不压测、不发大量畸形包、不触发无限循环
不公开未修复漏洞修复前不写公众号、不发群、不上短视频。更不能用漏洞向企业要钱——那是敲诈勒索，不是赏金
留痕保留你的请求日志和截图。万一被质疑，这是你证明"我在授权范围内测试"的唯一凭据

第 1 周装 Burp，在你自己的靶场（localhost:3000）上把 7 关用 Burp 重做一遍，不许用 curl，全部走 Repeater把 Burp 的操作练成肌肉记忆
第 2 周PortSwigger Academy 从最基础的注入、认证、访问控制三个模块开始，每天 2–3 关建立"漏洞类型 → 测试手法"的对应关系
第 3 周注册补天 / 漏洞盒子，先读规则页和已公开的漏洞报告，不急着提交。看别人怎么写的搞清平台的 scope 表达方式和报告标准
第 4 周挑一个防护较弱、竞争少的授权项目，只做三件事：看 robots.txt 和目录、翻 JS 找接口、测越权跑通第一次"挖到 → 通过 → 拿到分"的完整闭环
如果这本手册你只记三件事：
① 先看授权，再动手。scope 之外的一切，技术再好也是犯罪；
② 先看，再打。信息收集占七成时间，找准入口后验证只要几分钟。别一上来就丢扫描器；
③ 只验证到最小可复现。这一条同时保护目标、保护你自己、保护你的账号。
